# KNOWN LIMITATIONS

As of Final Vendor Decision Gate, the following verified boundaries and operational requirements apply to DeepChart:

1. **Docker Staging Verified:** Docker Desktop and Docker Compose staging environment are fully verified (Caddy reverse proxy, backend API, WebSocket, SQLite persistence, and container health checks all passing).
2. **Databento Live Market Data (BLOCKED - Operator Required):** Live Data vendor integrations operate under fail-closed protection. Connecting to live CME market feeds requires the Release Operator to supply a valid `DATABENTO_API_KEY` with active GLBX.MDP3 entitlements. Real high-throughput vendor feeds have not been validated against live production exchanges.
3. **Stripe Production Live Mode (NOT VERIFIED - Test Mode Verified):** Webhook signature validation, event-level deduplication idempotency (`webhook_events`), subscription lifecycle, and expired entitlement revocation are verified. Production live payment charges and live customer portal sessions require operator production keys (`STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`).
4. **Analytics Vendor Verification:** Core analytical engines (Footprint delta ladder, Volume Profile, Black-Scholes Greeks, GEX profile) are mathematically verified via synthetic fixtures and fail-closed invariants. Full end-to-end verification against un-sanitized live vendor ticks remains pending live data verification.
5. **Memory Profiling Scope:** Client memory was validated across 50 mount/unmount cycles in Playwright E2E stress testing (<25 MB delta). Sustained multi-day production profiling under thousands of real concurrent connections is pending live deployment telemetry.
6. **Single Node SQLite Architecture:** The SQLite WAL approach operates strictly as a single-node host deployment. Multi-node horizontal scaling of backend app instances sharing the SQLite file is unsupported and would risk data corruption.
7. **WAL-Safe Backup Prerequisite:** Hot backups of SQLite must always use SQLite Online Backup API (`sqlite3 ... ".backup ..."` or `scripts/backup_db.mjs` / `VACUUM INTO`). Plain file copies (`cp`) of `market_data.sqlite` without WAL checkpoints risk inconsistent state.
8. **Databento Plan Redistribution Restriction:** The Databento Standard Plan ($199/month per dataset) is legally and contractually restricted to **Internal Use Only**. Commercial redistribution or external customer terminal display requires the Databento Plus Plan ($1,750/month with annual contract) or Unlimited Plan ($4,500/month with annual contract). Crucially, the Plus plan does **not automatically grant full redistribution rights**; subscribers must obtain explicit exchange approval and execute an Information License Agreement (ILA) with CME / OPRA for their specific use case.
9. **Unconfirmed Exchange & Vendor Pricing:** All quoted CME Group and OPRA fee schedules represent general exchange reference schedules. They must NOT be treated as final binding quotes until Databento and exchange licensing authorities formally approve DeepChart's specific scope-of-use (Display vs Derived vs Non-Display).
10. **Volume Profile Data Provenance & Completeness Contract:**
   - **Provenance (`EXACT` | `ESTIMATED` | `UNAVAILABLE`):** Defines the mathematical accuracy of price-level volume attribution. `EXACT` indicates all volume and delta levels were calculated from exchange-executed raw trades with bid/ask aggressor attribution. `ESTIMATED` indicates synthetic volume distribution calculated from OHLCV bars via heuristic splitting. `UNAVAILABLE` indicates absence of trade data.
   - **Coverage (`COMPLETE` | `PARTIAL` | `UNKNOWN`):** Defines temporal completeness across the requested range `[startTime, endTime]`. The presence of trades in the database does **NOT** imply completeness. Unless an `ingestion_checkpoints` record explicitly confirms full range ingestion with status `COMPLETE`, the system fails closed to `coverage: 'UNKNOWN'`.
   - **Degradation Rules:** Coverage is marked `PARTIAL` if the trade query limit (25,000) is hit, if a recorded feed reconnect gap overlaps the range, or if the requested range extends outside the verified checkpoint window.
   - **Zero-Trade Session Invariant:** A quiet or overnight session interval with 0 trades is **NOT** marked `PARTIAL` if an ingestion checkpoint confirms full sequence continuity without gaps. It is reported with `available: true`, `status: 'no_data'`, `provenance: 'EXACT'`, `coverage: 'COMPLETE'`, and `totalVolume: 0`.
   - **UI Transparency:** The terminal explicitly displays granular status badges (`EXACT · COMPLETE`, `EXACT · PARTIAL`, `EXACT · UNVERIFIED`, `ESTIMATED`, `UNAVAILABLE`) to prevent unverified or partial profiles from ever masquerading as complete institutional profiles.
11. **Application Cost Cap Scope:** `DATABENTO_COST_CAP_USD` only limits historical REST API queries in application code. It does NOT cap fixed vendor subscription fees ($199/mo or $1,750/mo), exchange licensing fees, or continuous TCP streaming data consumption.
12. **OPRA Options Integration Deferred:** To minimize initial operational cost ($1,500/month vendor fee + exchange subscriber fees) and regulatory complexity, OPRA Options data integration is deferred until CME Futures live feed validation is proven and commercial demand is verified.
13. **Historical-Only Validation Strategy Prerequisite:** Operator should validate raw trade ingestion, exact volume profiles, and unit price lookups via usage-based historical queries under the Databento trial credit before committing to any live recurring subscription.
